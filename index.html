    Briefing

    Rules & getting started

    How it works

    • Each challenge hides a flag. Find it, paste it in, score points.
    • Flags look like NxT{some_text_here}. Submit the whole thing, braces included.
    • Flags are case-sensitive unless a challenge says otherwise.
    • Hints are free and only you see them. Use them when you're stuck. That's how you learn.
    • Ties are broken by who reached the score first.

    No AI

    This is a beginner comp. The point is for you to learn how this stuff works, so AI is off the table for the whole 2 hours.

    • No chatbots or AI assistants: ChatGPT, Claude, Gemini, Copilot, DeepSeek, Perplexity, Grok, Meta AI, or anything like them.
    • No AI built into other tools either: AI code completion in your editor, AI browser sidebars, AI "explain this" buttons, AI image analysis.
    • Don't paste challenge text, files, code or screenshots into any AI, and don't ask AI to write a script for you.
    • Search engines are fine, but skip the AI summary at the top (Google AI Overviews, Bing Copilot answers) and read real pages instead.
    • Not sure if a tool counts? Ask an organizer before you use it.

    What you can use

    • Search engines, documentation, Stack Overflow, Wikipedia, YouTube tutorials.
    • Writeups from other CTFs, to learn a technique you haven't seen before.
    • Normal (non-AI) tools like the ones listed below, plus scripts you write yourself.
    • The hints. They're free, so use them.
    • Organizers. Ask us if you're stuck or think a challenge is broken. We'll nudge, not solve.

    Play fair

    • Solo play. One account per person, and don't log in to anyone else's.
    • Don't share flags, answers or step-by-step help with other players during the comp. Swapping techniques after it ends is encouraged.
    • Only attack the challenge pages under /chal/. Leave the scoreboard, the login and the server itself alone.
    • No automated scanners or flooding (sqlmap, dirbuster, gobuster, nikto, DoS). None of the challenges need them.
    • Don't brute-force the flag box. It's rate limited anyway.
    • Found a bug that gives you flags you didn't earn? Tell an organizer instead of using it.

    If you break the rules

    • Organizers can see every submission. Suspicious solves may get a "walk us through it" question.
    • Breaking the rules gets your solves removed or gets you hidden from the scoreboard. Organizer decisions are final.
    • Honestly, the only person you'd be cheating is yourself. A 300-point flag you didn't understand teaches you nothing.

    Useful tools

    • CyberChef: decoding, encoding and data wrangling in the browser
    • Your browser's DevTools (F12): view source, network, cookies
    • Wireshark: opening .pcap network captures
    • exiftool, strings, file, a hex editor (hexed.it)
    • Aperi'Solve: image steganography checks
    • curl for sending hand-crafted web requests (built into Windows 10+, macOS and Linux)
    • Python 3 for scripting anything

    Speed Math solved easy4 solves100

    Archive version: the archived Speed Math runs in your browser, so the API and the scripts below only worked on the live comp server.

    Flag: NxT{you_can_count_fast}

    What it teaches: talking to an interactive service from a script. Lots of CTF challenges throw dozens of questions at you with a short timer, so you have to automate them.

    By hand

    Open the page, hit Start, and answer 5 questions with 15 seconds each. A calculator helps. Watch out for negative answers.

    Look under the hood

    DevTools → Network while you play shows the page is just calling two endpoints:

    • POST api/start → {"round": 1, "total": 5, "question": "96 * 78", "timeLimit": 15}, and sets a mathsid cookie
    • POST api/answer with {"answer": 7488} → the next question, an error, or finally {"flag": "NxT{...}"}

    The mathsid cookie is how the server remembers your game. Lose the cookie and it has no idea which question you're answering.

    With a script (the skill that actually matters)

    import requests

URL = "https://<comp-link>/chal/misc-speed-math/"

s = requests.Session()          # a Session keeps cookies between requests
q = s.post(URL + "api/start").json()
while "question" in q:
    print(q["question"])
    q = s.post(URL + "api/answer", json={"answer": eval(q["question"])}).json()
print(q)

    (pip install requests if you don't have it.)

    The same idea with curl, saving and resending the cookie by hand:

    curl -c jar.txt -X POST https://<comp-link>/chal/misc-speed-math/api/start
curl -b jar.txt -c jar.txt -H "Content-Type: application/json" -d '{"answer": 7488}' https://<comp-link>/chal/misc-speed-math/api/answer

    ⚠️ eval() is fine here because we know exactly what the server sends. Never eval() untrusted input in real code.

    Next step: many CTFs serve challenges like this over raw TCP (nc host port) instead of HTTP. Same idea, different transport. Look up Python's socket module and the pwntools library.

    A big part of beginner "crypto" is telling encoding (reversible by anyone, no key: Base64, hex) apart from encryption (needs a key: Caesar, XOR, RSA). Learn to recognise encodings by sight:

    Looks likeProbably
    A-Z a-z 0-9 + /, ends with = or ==Base64
    0-9 a-f only, even lengthHex
    A-Z 2-7 only, padded with =Base32
    Letters shifted, punctuation untouchedCaesar / ROT13

    Et Tu, Brute? solved easy3 solves100

    Flag: NxT{caesar_would_be_proud}

    The ciphertext starts UeA{. We know the plaintext starts NxT{, so the last letter T→A is a shift of 7 (T=19, A=0, and 19+7=26≡0). Shift every letter back by 7.

    • CyberChef: "ROT13" with amount 19 (that's −7 mod 26)
    • dcode.fr Caesar cipher → brute force shows all 25 options
    ct = "UeA{jhlzhy_dvbsk_il_wyvbk}"
for shift in range(26):
    pt = "".join(chr((ord(c) - 97 - shift) % 26 + 97) if c.islower()
                 else chr((ord(c) - 65 - shift) % 26 + 65) if c.isupper() else c for c in ct)
    if pt.startswith("NxT"):
        print(shift, pt)

    Takeaway: with only 25 possible keys, brute force is instant. Known plaintext (the flag format!) tells you the key directly.

    Onion Layers solved medium1 solve200

    Flag: NxT{cyberchef_is_your_friend}

    Peel one layer at a time, and after each step ask "what does this look like now?"

    1. onion.txt is Base64 → decode → you get a long hex string
    2. Hex (0-9a-f) → decode → you get uppercase letters, digits 2–7 and = padding
    3. That's Base32 → decode → GENVA{plorepurs_vf_lbhe_sevraq}
    4. Letters look shifted, braces untouched → ROT13 → flag

    CyberChef: From Base64 → From Hex → From Base32 → ROT13. CyberChef's Magic operation (with "Intensive mode") can find most of these on its own.

    import base64, codecs
s = open("onion.txt").read().strip()
s = base64.b64decode(s).decode()
s = bytes.fromhex(s).decode()
s = base64.b32decode(s).decode()
print(codecs.decode(s, "rot13"))
    XOR Marks the Spot solved medium0 solves200

    Flag: NxT{single_byte_xor_is_weak}

    XOR facts you need:

    • a ^ a = 0 and a ^ 0 = a, so p ^ k ^ k = p. XOR undoes itself.
    • If c = p ^ k, then k = p ^ c. Knowing one plaintext byte reveals the key.

    The first ciphertext byte is 0x14. The first plaintext byte is N = 0x4e. Key = 0x14 ^ 0x4e = 0x5a.

    • CyberChef: From Hex → XOR (key 5a, hex), or XOR Brute Force and search for NxT
    data = bytes.fromhex("0e081b131421...")  # paste the full hex
key = data[0] ^ ord("T")
print(bytes(b ^ key for b in data).decode())

    Takeaway: single-byte XOR has only 256 keys. Repeating a short key is barely better, and known plaintext breaks it the same way.

    Too Close for Comfort solved hard0 solves300

    Flag: NxT{close_primes_are_bad_primes}

    RSA in 30 seconds:

    • Pick primes p, q. Public modulus n = p*q. Public exponent e (usually 65537).
    • φ(n) = (p-1)(q-1). Private key d = e⁻¹ mod φ(n).
    • Encrypt: c = mᵉ mod n. Decrypt: m = cᵈ mod n.
    • Security depends entirely on n being hard to factor.

    A 512-bit n would normally take serious compute to factor. But the description says q was found by counting up from p, so p ≈ q ≈ √n. Fermat's method writes n = a² − b² = (a−b)(a+b) and searches upward from a = ⌈√n⌉. When p and q are close, b is tiny and it finishes in a handful of steps.

    from math import isqrt

n = ...  # from output.txt
e = 65537
c = ...

a = isqrt(n) + 1
while True:
    b2 = a * a - n
    b = isqrt(b2)
    if b * b == b2:
        break
    a += 1
p, q = a - b, a + b
assert p * q == n

d = pow(e, -1, (p - 1) * (q - 1))
m = pow(c, d, n)
print(bytes.fromhex(hex(m)[2:]).decode())

    No-code alternative: paste n into alpertron.com.ar/ECM.HTM. It tries Fermat-style tricks automatically. Then use dcode.fr's RSA decoder with p, q, e and c.

    Takeaway: RSA is only as strong as your primes. Other classic beginner RSA weaknesses to look up: small e with small m, shared primes between keys, and n that's on factordb.com.

    The forensics starter kit: file (what is this really?), strings (any readable text?), exiftool (metadata?), a hex editor (look at the raw bytes), binwalk (anything embedded?), and Wireshark for network captures. Running the first four on every file takes 30 seconds and solves a surprising number of challenges.

    Homework solved easy2 solves100

    Flag: NxT{file_extensions_lie}

    $ file homework.txt
homework.txt: Zip archive data ...

    The first two bytes are PK (after Phil Katz, inventor of ZIP). Rename to .zip and extract, or run unzip homework.txt. The flag is in notes/flag.txt.

    Takeaway: the extension is just part of the name. Magic bytes tell you the real type. Worth memorising: PK = ZIP (also .docx/.jar/.apk), \x89PNG = PNG, \xFF\xD8\xFF = JPEG, %PDF = PDF, \x7FELF = Linux executable, MZ = Windows executable.

    Flag: NxT{MAGIC_BYTES_MATTER}

    Sniffed solved medium2 solves200

    Flag: NxT{plaintext_passwords_on_the_wire}

    1. Open capture.pcap in Wireshark.
    2. Filter: http.request.method == "POST" → one packet, POST /login.

    3. Right-click → Follow → TCP Stream. You'll see:

      username=jsmith&password=NxT%7Bplaintext_passwords_on_the_wire%7D
    4. URL-decode it (%7B = {, %7D = }). Wireshark's packet details pane also shows the decoded "HTML Form URL Encoded" fields.

    Nothing To See Here solved hard1 solve300

    Flag: NxT{least_significant_but_most_important}

    A real cat photo, but the first few hundred colour values carry a hidden message. LSB steganography. Each pixel has R, G, B values from 0–255. Changing the lowest bit (e.g. 200 → 201) is invisible to the eye, but each pixel can then carry 3 hidden bits.

    The fastest route: upload to aperisolve.com or run zsteg nothing.png and look at the b1,rgb,lsb,xy line.

    By hand with Python + Pillow (pip install pillow):

    from PIL import Image

img = Image.open("nothing.png").convert("RGB")
bits = [v & 1 for px in img.getdata() for v in px]   # R,G,B lowest bits, row by row
out = bytearray()
for i in range(0, len(bits), 8):
    byte = int("".join(map(str, bits[i:i + 8])), 2)  # most significant bit first
    if byte == 0:
        break
    out.append(byte)
print(out.decode())

    Takeaway: for any image challenge, run the stego checklist: strings → exiftool → binwalk → zsteg/Aperi'Solve → look at individual bit planes (StegSolve or StegOnline).

The golden rule of web security, and the theme of this whole category: everything the client sends can be changed by the user. Cookies, headers, hidden form fields, JavaScript checks, IDs in URLs: all of it.

    Members Only solved medium0 solves200

    NoteKeeper solved medium1 solve200

    rev

    3 writeups

    Reverse engineering means working out what a program does without (good) source code, then using that knowledge. These three start easy: source you can read, source you can change, and bytecode. Next steps after this comp: compiled C binaries in Ghidra (free, from the NSA).

    Flag Checker 3000 solved medium0 solves200

    Flag: NxT{xor_and_add_reversed}

    for i, ch in enumerate(flag):
    if ((ord(ch) ^ 0x42) + i) % 256 != enc[i]:
        return False

    For each character: XOR with 0x42, then add the position i. To reverse it, undo the steps in the opposite order: subtract i, then XOR with 0x42 (XOR undoes itself).

    enc = [...]  # copy from checker.py
print("".join(chr(((e - i) % 256) ^ 0x42) for i, e in enumerate(enc)))

    Run python checker.py and paste the result to confirm.

    Takeaway: most "checker" challenges are a chain of reversible steps. Write down each operation, then invert them from last to first.

    License Check solved medium1 solve200

    Flag: NxT{you_control_the_code}

    The license is checked against a SHA-256 hash, and you can't reverse a hash. But the reward is computed by unlockReward(), which needs no license at all. The if just guards whether it gets called.

    Change:

    if (hash === VALID_LICENSE_HASH) {

    to

    if (true) {

    and run node license.js. Or add console.log(unlockReward()); at the end, or paste the reward array and unlockReward function into your browser console.

    Takeaway: if code runs on your machine, you control it. That's why software license checks get cracked, and why secrets must never live in client-side code. In compiled programs the same trick is called "patching a jump".

    Lost in Translation solved hard1 solve300

    Flag: NxT{bytecode_is_readable}

    Python runs code on a stack machine. Read the disassembly one source line (the numbers on the left) at a time:

    LineBytecode gistPython
    2–3len(flag), 25, != → RETURN Falseif len(flag) != 25: return False
    4–5flag[None:4], 'NxT{', !=if flag[:4] != "NxT{": ...
    6–7flag[-1], '}'if flag[-1] != "}": ...
    8flag[4:-1].split('_') → partsparts = flag[4:-1].split("_")
    9–10len(parts) != 3three words separated by _
    11–12parts[0][None:None:-1], 'edocetyb'parts[0][::-1] == "edocetyb" → parts[0] = "bytecode"
    13–14chr(105) + chr(115)parts[1] == "is" (105 = i, 115 = s)
    15–16parts[2], 'readable'parts[2] == "readable"

    Put it together: NxT{ + bytecode + _ + is + _ + readable + } = 25 characters. ✔

    Takeaway: bytecode looks scary but it's very regular. LOAD_* pushes values, operations pop them, and each POP_JUMP_IF_* is an if. The same patient, line-by-line approach works for Java bytecode, .NET IL, and eventually assembly.
